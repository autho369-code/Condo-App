A production backup still needs restoration into a disposable environment and rollback must be rehearsed before applying branch migrations to production.

Catalog-only reports that do not have an audited data source must remain visibly unavailable until implemented; every supported report/export still needs fixture-to-journal/control-account reconciliation.
4. **Complete the remaining deployed identity/storage testing.** Role/RLS, redirects, direct IDs, stale tokens, service-only RPC ACLs, forbidden mutations, private/path-bound/expiring document capabilities, MIME denial, invitation assignment/replay/recipient checks, and durable invitation/reset controls pass. Deployed-browser rollback/rate-limit behavior, password-recovery delivery, report retention, remaining workflow-specific signed-upload issuance, and any supported tenant persona remain release gates.
5. **Prove production operations.** Validate Preview and Production environment configuration without printing secrets; verify cron authentication, alert delivery, backup restoration, rollback, rate limits, and notification suppression. Then obtain owner approval for the exact commit.
6. **Run the controlled release sequence.** Merge only after all preceding gates pass, deploy the approved commit, and perform read-only production smoke tests. Production remains frozen until then.
