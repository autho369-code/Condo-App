# Release blockers

1. **Prove backup recovery and rollback.** The repository has 187 valid unique migration versions, the full chain replays from an empty local database, and linked staging is current. A production backup still needs restoration into a disposable environment and rollback must be rehearsed before applying branch migrations to production.
2. **Complete provider test-mode accounting proof.** Exercise Stripe Connect and Plaid with signed webhooks, duplicates, out-of-order delivery, failures, refunds/disputes, payouts, reconciliation, and source-linked GL tie-outs. No live money may be used for this gate.
3. **Finish the report truthfulness matrix.** Core statements and a real Balance Sheet PDF now pass in staging. Catalog-only reports that do not have an audited data source must remain visibly unavailable until implemented; every supported report/export still needs fixture-to-journal/control-account reconciliation.
4. **Complete authorization and storage attack testing.** Staging role/RLS, role-home redirects, cross-tenant page IDs, report-run IDs, and private report-object access pass for the tested personas. API mutation attempts, signed-URL expiry/retention, upload MIME/path isolation, stale sessions, invitations/resets, and any supported tenant persona remain release gates.
5. **Prove production operations.** Validate Preview and Production environment configuration without printing secrets; verify cron authentication, alert delivery, backup restoration, rollback, rate limits, and notification suppression. Then obtain owner approval for the exact commit.
6. **Run the controlled release sequence.** Merge only after all preceding gates pass, deploy the approved commit, and perform read-only production smoke tests. Production remains frozen until then.
