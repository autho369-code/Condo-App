# Portier369 Competitive Program Baseline

**Evidence date:** August 3, 2026
**Scope:** Platform operator, management-company admin, manager, board, owner, tenant/resident, and vendor experiences
**Decision:** Development **GO**; broad production release **NO-GO** until the release blockers below close

## Evidence standard

This baseline separates three kinds of evidence:

- **Verified in Portier369:** inspected source, database migrations, automated tests, staging data, generated PDFs, or authenticated browser execution.
- **Vendor-published:** a capability appears on the competitor's current official product or help site. This verifies the public claim, not every paid-plan screen or edge case.
- **Access verification pending:** an authenticated competitor workspace is required to establish screen-level parity. No superiority claim is made from marketing copy alone.

## UX audit

### Fixed immediately

- Added a focused TOTP enrollment/challenge flow with recovery guidance, clear errors, numeric one-time-code input, and no phone-number dependency.
- Added account access to the two-step verification status.
- Replaced the misleading Security Center session-timeout column with an explicit statement that timeout is not displayed until enforcement is real.
- Added Portier-recorded sign-in activity to the operator Security Center.

### Backlog

- Add route-level `loading.tsx`, `error.tsx`, and contextual `not-found.tsx` coverage, starting with finance, payment, document, and portal routes.
- Replace the sidebar phrase “Find a workspace” where it only filters navigation.
- Add a unified case timeline so owners, boards, managers, and vendors see one status/history/next-action model.
- Add native-install/PWA resilience only after the existing offline inspection queue has measurable field validation.

### Explicitly rejected

- Copying any competitor's page structure, labels, icons, branding, or copyrighted help text.
- Adding leasing syndication and tenant screening solely to match rental-focused products. These are outside the core HOA/condominium operating model until a paying customer requires them.

## Security audit

### Verified

- Staging tenant, association, role, invitation, storage, stale-session, and service-only RPC gates pass.
- Current source passes the high-confidence secret scan.
- The `record_login_attempt` and rate-limit RPCs are service-role-only under the existing SECURITY DEFINER boundary migration.
- MFA policy is now resolved from platform-operator status, per-profile requirements, and portfolio admin/staff settings.
- A password-verification hook is implemented and locally verified at the Supabase Auth boundary, including direct GoTrue requests and application enrichment without duplicate rows. Hosted activation is blocked by the organization’s current hook entitlement (Supabase returned HTTP 402 on staging config push).

### Release blockers

- The MFA/login-protection branch must be independently reviewed, browser-tested against staging, merged, and deployed.
- Upgrade/configure hosted Supabase to enable and verify the password-verification hook, or activate production Turnstile/hCaptcha; app-only throttling cannot secure direct GoTrue requests.
- Per-session idle timeout is not implemented.
- Audited manager, company-user, platform-operator, and break-glass authenticator recovery are implemented on the branch; the staged lost-authenticator exercise remains a release gate.
- Security certification claims such as SOC 2 are not made because no audit evidence exists.

## Performance audit

- Production build passes and generates 157 static pages; the new MFA client route is 5.76 kB with a 187 kB first-load bundle.
- Three pre-existing raw-image warnings remain in login branding, board violation evidence, and the shared sidebar.
- Heavy PDF code paths still use static `jspdf` imports; dynamic loading remains a bundle/backlog item.
- Route-level streaming/loading coverage is weak even though server data queries commonly run in parallel.

## Accounting audit

### Verified

- Double-entry invariants, AP approvals, checks, void/stop/reissue/reversal, bank reconciliation, accounting periods, and fifteen staging reports pass.
- The staging monthly package balances and rendered correctly across nine visually inspected pages.

### Release blockers

- Rebuild 1099 totals from actual eligible cash disbursements, not bill face values; support the correct form/box decision and association-specific payer scope.
- Reconcile provider-generated settlement data against ledger postings once Stripe/bank production onboarding is complete.
- Add a financial-package review/sign-off state before scheduled delivery.

## Prioritized backlog and classification

### P0 — release integrity

1. **Fixed immediately:** enforce MFA; additive login limits; Auth-boundary sign-in audit; truthful Security Center; audited administrator MFA recovery.
2. **Backlog:** production-safe per-session idle timeout and forced revocation.
3. **Backlog:** filing-grade 1099 cash-disbursement model and reconciliation tests.
4. **Backlog / external dependency:** activate Supabase bot protection, then certify Stripe, bank feeds, Twilio/phone, and physical-mail delivery in staging and production.
5. **Fixed / release gate:** the operator recovery runbook and guarded break-glass tool are implemented; complete a staged lost-authenticator exercise before production.

### P1 — market-defining HOA workflows

1. Complete electronic elections, secret ballots, quorum and proxy tracking.
2. Add resale/estoppel orders, questionnaires, fees, packet generation, attestation and delivery.
3. Add visitor, package, concierge incident, patrol and shift-handoff workflows.
4. Add AI decision/audit ledger and cited governing-document/financial answers.
5. Add unified case ownership/timeline and route-level loading/error resilience.
6. Add smart maintenance routing, SLA cockpit and stakeholder scheduling.

### P2 — scale and ecosystem

1. Enterprise SSO/SAML.
2. Certified partner/API marketplace and webhooks by customer demand.
3. Native mobile applications if installable web/offline field metrics prove insufficient.

### Rejected for now

1. Rental listing syndication, lead-to-lease CRM, and tenant screening without an HOA-customer requirement.
2. Unsupported “better than every competitor” marketing claims before authenticated workflow evidence and customer outcome data exist.
3. Broad marketplace integrations without a signed design partner or measurable workflow benefit.

## Implementation plan

1. **Account security release:** close independent review, stage MFA, verify enrollment/challenge/recovery and all seven roles, then merge through PR.
2. **Accounting integrity:** rebuild and certify 1099; add report review/sign-off and cited financial narrative.
3. **Payments and communications:** complete Stripe/bank/Twilio/mail provider certification with replay, reconciliation and failure evidence.
4. **Governance:** ship elections, secret ballots, proxies, quorum and immutable result packets.
5. **Resident operations:** ship resale fulfillment and front-desk visitor/package/incident workflows.
6. **Operational intelligence:** unified cases, AI audit ledger, sourced assistants, maintenance SLA/routing.
7. **Resilience and scale:** loading/error boundaries, bundle splitting, enterprise identity, observability and performance budgets.

Each slice follows: protected branch → tests → staging fixtures/migrations → role and tenant boundary checks → PDF/browser verification where applicable → independent Claude review → PR/CI → approved production deployment → read-only smoke test.
