# security-reviewer memory

## Confirmed rules (Mirsad)
- The board portal is read-only. Owners and vendors change only what their portal explicitly offers, on their own records (vendor work-order status, owner profile/payments/reservations/insurance). Nobody outside staff sees manager notes.

## False alarms to skip
- Webhooks and cron routes have no signed-in user: a verified signature or `requireCronSecret` is their auth. (Codex on PR #229.)

## Recurring mistakes
- `communications_log` RLS only checks `portfolio_id`: writes into another association pass RLS unless `managesAssociation` is checked (see `lib/rpcs/notifications.ts`).
- Service-client undo/cleanup must be pinned to the exact row id plus `portfolio_id`.

## Helpers / files worth checking
- Tenant headers (`x-tenant-host`, `x-portfolio-id`, ...) are trusted only because `middleware.ts` `INTERNAL_TENANT_HEADERS` strips client copies first; any new internal header must be added there.
- `portfolios` column guards are triggers: `portfolios_guard_platform_columns` (tier, slug, custom_domain...; passes when `auth.uid() is null` or platform admin) and `portfolios_guard_domain_verification` (custom_domain_verified_at; blocks `current_user in ('authenticated','anon')`, so only service role/SQL editor write it). Prefer the `current_user` check for new guards: `auth.uid() is null` also passes anon. New platform-owned columns must join one.
- Auth/Supabase redirect links (reset, invite callback) must stay on `tenantWorkspaceUrl`/`resolvedTenantUrl`; `companyUrl` (verified custom domain) is for plain links only.

- `portfolios` SELECT: staff/company admin only for `current_portfolio_id()` (`portfolios_staff_read`), operators all (`portfolios_platform_read`); owners/board/vendors none. A non-`!inner` `portfolios(company_name)` embed hidden by RLS returns null, not an error. `associations.portfolio_id` is the only FK to portfolios (no ambiguity; precedent `app/(app)/payments/[id]/receipt/page.tsx:24`).
- `me.portfolio` is the caller's profile company, not the record's: operators pass `requireStaff` and see every company, so branding/scoping by `me.portfolio` can mismatch the association (e.g. `lib/rpcs/documents.ts:92`). Prefer the record's own `portfolio_id`.

- Two writers of `portfolios` branding: `app/company-admin/settings/actions.ts` (RPC `update_company_profile`) and `app/(app)/settings/branding/page.tsx` saveBranding; both validate via `lib/company-admin/settings.ts` (`isHexColor`, `normalizeCompanyLogoUrl`, `normalizeWebsiteUrl`, trimmed non-blank name). DB backs it since 20261007050000 (`portfolios_brand_color_hex`, `portfolios_company_name_not_blank`), and `middleware.ts` falls back to #10B981 for non-hex `x-portfolio-color`. Any new raw (non-`setEncodedHeader`) tenant header needs the same allow-list. `support_email` is still free text (used as email replyTo) -- low, pre-existing.
- `.bind(null, id)` args on server actions are NOT encrypted (client can send any); never fall back to them for scoping. `updatePortfolioPolicy` (lib/rpcs/portfolio.ts) fixed 2026-10-07 to ignore it and require `me.portfolio.id`.
- Direct `portfolios` updates hit 0 rows (no error) for callers RLS excludes; check for `.select('id')` + empty-result failure.

- White-label via `me.portfolio` (audit 2026-10-08): emails whose `portfolioId` is the record's company but `fromName`/`replyTo`/`tenantWorkspaceUrl(me.portfolio.slug)` come from the caller's profile company break for operators (requireStaff passes them). Inserts there must take portfolio_id from the validated owner/association, not `me.portfolio` (operators). Fixed 9bc7a0f5 via `currentHome()` (RLS-read current occupancy + `associations(portfolio_id)` embed; fails closed if hidden). Pattern: a fail-loudly lookup placed AFTER writes (e.g. `recipientCompany` after revoke+insert in `sendTenantPortalInvitation`) leaves partial state; resolve lookups before the first write.
- Form-supplied FK ids are not RLS-checked by the FK. `associations.property_group_id` app writers (associations/new, createBuilding, setPropertyGroupMembers) check the group's portfolio since 2026-10-08, and migration 20261008030000 backs it in the DB (associations + property_groups triggers; `report_data_property_group_directory` join now filters by portfolio). ## Missed checks (caught later)
- A public "prove you are us" endpoint (e.g. `/api/tenant/domain-check`) must bind its HMAC to a fresh verifier-chosen challenge; a deterministic proof can be recorded and replayed after a domain takeover. I suggested only HMAC-keying it; Codex caught the replay (PR #232).
- A fresh challenge stops replay but not a live relay: a domain holder can forward each check to us with the right Host and pass our answer back. Domain ownership checks must also confirm public DNS points at our hosting (`lookupDomain` + `pointsAtVercel`). Codex, PR #232.
- A "verified at" timestamp written by a cron must expire (trust only recent checks), or a stopped job/archived company leaves it trusted forever. Codex, PR #232.
- `next.config.mjs` `redirects()` run before `middleware.ts` (no auth/tenant checks on the hop) and pass the query string through; safe only with a fixed internal destination whose own route is guarded. A `:param` in `destination` host/path would be an open-redirect risk.
- `user_invitations.token` (20261007040000): CHECK `^[0-9a-f]{64}$` + invoker trigger `user_invitations_server_token` mints the token when `current_user in ('authenticated','anon')` and refuses token changes. Closed the guessable-token path (staff insert / company-admin update could pick one). Pattern for caller-chosen secrets: format check alone is not enough; mint server-side by `current_user`. Invoker-trigger caveat: `provision_portfolio`/`create_invitation` are INVOKER, so their tokens are replaced too; fine because they read it via RETURNING. A new SECURITY DEFINER path that takes a token parameter would bypass the trigger.
- EXECUTE is not checked when a trigger fires (only at CREATE TRIGGER), so the event trigger revoking trigger-function EXECUTE (20261001031000) never breaks triggers.
- `public.html_escape` escapes `& < > " '` since 20261007040000. Its output goes only into `email_queue.body`, which is sent as HTML (`app/api/email/process-queue/route.ts`), and shown as text after decoding `&#39;` (`communication-center/emails/[id]/page.tsx` plainText). Subjects never use it. Check new callers do not put it in subjects or plain-text bodies.
- Other token columns: `invitations` (legacy, RLS on, no policies) and `owner_portal_invites.token` (unused by code). Neither is rendered; ignore them unless code starts using them.
- `portfolios.slug` is CHECK-constrained (`portfolios_slug_format`, 2-32 chars) + `reserved_portfolio_slug`; a looser SQL slug regex is not a host-injection risk, just inconsistent with `lib/tenant/host.ts` PORTFOLIO_SLUG.
- `create or replace function` keeps the existing ACL; service-only list lives in 20260726050000 (`render_invitation_email`, `queue_*`).
- Query-param banner lookups (`MESSAGES[sp.x]` on a plain object literal) resolve `__proto__`/`constructor`/`toString` to truthy non-strings; rendering them as a React child crashes or blanks the page. Require `Object.hasOwn(...)` or a `Map` (seen `app/(app)/settings/page.tsx` SAVED_MESSAGES, 2026-10-07).
- AI routes (`app/api/ai/*`): BYO key lives in `portfolios.ai_api_key_ciphertext`, decrypted only in `lib/ai/service.ts` `getAIConfig` (errors are generic, no key text); `me()` redacts AI credentials (20261001090317). Snapshot/tools use the user session + `.eq(portfolio_id, me.portfolio.id)`. `is_finance_staff()` already includes `hoa_role='company_admin'`, and `can_access_portfolio` includes company admins, so `requireWorkspaceStaff` on AI routes is a safe widening (reviewed 2026-10-07, no findings). The Next `redirect()` thrown by guards inside route `try/catch` becomes a 401: intended, not a swallowed error.
- `buildPortfolioSnapshot(portfolioId)` (lib/ai/portfolio-snapshot.ts) trusts its argument (only caller passes `me.portfolio.id`); operators' RLS sees every company, so any new caller must pass `me.portfolio.id`, never request input. `isAIConfigured` (lib/ai/service.ts) returns boolean only; safe with service client when pinned to `me.portfolio.id` (PR #242, no findings).
- Storage cleanup via service client after an RLS-session delete: require `.delete(...).select('id')` to return the row AND `isScopedStoragePath(path, ns, entityId)` before `svc.storage.remove`. A 0-row RLS delete is not an error (e.g. meeting_documents SELECT is wider than DELETE for assistant managers), and staff can rewrite path columns via PostgREST (`owner_attachments.file_path` has no CHECK). Seen `app/(app)/meetings/[id]/actions.ts:292-296`, `app/(app)/owners/[id]/financial-actions.ts:104-108` (2026-10-07).
- Payable-bill RPCs (`void_payable_bill`, `approve_payable_bill`, `request_payable_bill_approval`) are SECURITY DEFINER with only `can_manage_finance(portfolio)`; owner-payable RPCs also check `can_manage_association` (`app_owner_payable_for_update`). Compare new finance RPCs to the latter.
- Silent-save sweep (2026-10-07, no blockers): `.select('id')` after an RLS update reads RETURNING through the SELECT policy, so check both UPDATE and SELECT policies (e.g. `insurance_owner_read` adds `insurance_certificate_path_matches`). Multi-step writes (`setPropertyGroupMembers` add then remove, `vendors/ach` bank upsert then vendor update, `maintenance` history then task, reordered 2026-10-08 to task-first with a state guard) leave earlier writes in place when the 0-row check fails: the message must say what was already saved; check `changed.length === expected`, not just non-zero, for `.in(...)` batches.
- Verified fixes (db2a329d): adding `.select('id')` to soft-delete updates is safe only when the table's SELECT policy has no `archived_at is null` filter (otherwise RETURNING hides the row and the action falsely errors); checked association_keys/notes/insurance/fees/unit_groups, committee_members, association_loans: none filter. Re-check this for new tables. `can_view_association_row(null)` is true, so SECURITY DEFINER RPCs mirroring it don't lock out association-less rows.
- Association scope already enforced by row triggers (fire inside SECURITY DEFINER, use auth.uid()): `payable_bills`/`payable_checks` (`enforce_payable_association_scope`, 20261003140000) and charges, unit_recurring_charges, occupancies, owner_statements, statement_batches, board_approval_settings, record_notes, tag_assignments, signature_requests, year_end_packages, payments (`enforce_row_association_scope`, 20261004130000). RPC checks on those tables are defense-in-depth; real gaps are tables WITHOUT a trigger (recurring_bills, delinquency_cases, bank_accounts, gl_account_map, accounting_periods). `operator_write_guard` trigger (20261005072000) covers operator writes on every RLS table.
- Update-path miss pattern: RPC checks the NEW association but not the EXISTING row's. Compare `save_purchase_order` (20261002133659). save_recurring_bill + delinquency RPCs fixed in 20261007090000.
- No live DB access here: reconstruct a function from its last full `create or replace` plus later `pg_get_functiondef` + `replace` patches (grep the function name across all migrations).

## Concurrency guards (2026-10-08)
- Missed (Codex, PR #249): a compare-and-set guard is only idempotent if the expected value comes from what the page rendered (hidden field like `seen_completed_at`, or a version), never from a fresh read inside the action. Re-reading lets a late duplicate or stale-page submit see the advanced row and complete the next occurrence too. Seen `app/(app)/maintenance/page.tsx` completeTask.
- Guarded updates (`.eq(col, readValue)` / `.neq('status', x)` + `.select('id')`) stop double submits only when the write changes the guarded value; a no-op step (e.g. `nextDue === due`) or a nullable status column (`neq` drops NULL rows) weakens them. `maintenance_tasks.status` is nullable text (active/paused/completed), `next_due_date` is `date`. Seen `app/(app)/maintenance/page.tsx` completeTask.
- Fix verified (2026-10-08): `complete_maintenance_task` (20261008020000) is INVOKER, CAS on the page's `seen_completed_at` (`is not distinct from`) + due date, all four writes in one txn. Fine to take `p_seen_due` from a fresh read when `last_completed_at` (which every completion changes) comes from the page. Notes go via `mergePrivateFieldsOne` -> history (staff-only RLS) and `calendar_events.internal_notes` (moved by `calendar_events_move_private_fields`).
- maintenance_tasks, calendar_events carry RESTRICTIVE `mgr_assoc_scope` (all commands); `maintenance_task_history` policy requires `can_access_association` of the parent task + `completed_by = auth.uid()`. No extra `managesAssociation` needed for user-session writes there.
- `/accept-invitation` (2026-10-08): page + `acceptInvitation` add a service-client `tokenMatchesAddress` check. That is a host-consistency guard, not a boundary: `accept_invitation` (SECURITY DEFINER, EXECUTE to authenticated) is callable directly via PostgREST from any origin; the real binding is pending + expiry + `lower(inv.email)=auth email` + verified-email trigger. `/invite` already shows company_name to anyone holding the token (unauthenticated), so showing it on the signed-in page leaks nothing new. Tokens are 64-hex, so no rate limit needed for enumeration.
- Tenant-host middleware (3355c8f0, 2026-10-08): robots.txt disallow-all + PLATFORM_ONLY_PATHS 404 + /demo,/legal in MARKETING_PATHS, all inside the resolved-tenant branch before `getUser`. Clean: nothing outside `app/(marketing)` links /demo or /legal (signup links /demo but /signup is already redirected on tenants); the `tenant-workspace-boundary.test.ts` pins it. Early returns there drop any refreshed cookies, same as the existing redirects (acceptable).
- Compensating writes on a lost race (e.g. archive the duplicate after a 0-row CAS link, `app/(app)/inspections/[id]/page.tsx:157`, 2026-10-08) are often left unchecked: require error + `.select('id')` check and say in the message what is left behind. RLS refs: `calendar_event_reminders_staff_scoped` (can_access_association / portfolio when assoc null) matches `calendar_events_staff_all` + `mgr_assoc_scope`; `work_orders_staff_all` lets staff archive, no `archived_at` filter on SELECT; WO insert fires `trg_dispatch_wo_created` webhook, so a duplicate archived later was still announced.

## Next.js pitfalls
- Inline `'use server'` actions capture outer-scope identifiers as encrypted bound args via Flight; a component-scope helper FUNCTION captured this way throws at render ("Functions cannot be passed directly") and breaks the whole page. Helpers used by inline actions must be module-scope. Seen `app/(app)/associations/[id]/committees/page.tsx:54` (2026-10-08). Verify with the SWC transform: scratch script calling `next/dist/build/swc` `transform` with `serverActions:{isReactServerLayer:true,isDevelopment:false,hashSalt:'',useCacheEnabled:false,cacheKinds:[]}` and grep `encryptActionBoundArgs`.
- Editing an already-applied migration does nothing live (`if not exists` guards skip); check Status.md for "Apply after merge" before trusting an edited migration.
