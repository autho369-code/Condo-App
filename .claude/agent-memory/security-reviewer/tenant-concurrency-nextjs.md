- `tenant_branding` (20261006060000) excludes archived portfolios, matches custom_domain without requiring verification (Vercel routing is the guard).

## Concurrency guards (2026-10-08)
- Missed (Codex, PR #249): a compare-and-set guard is only idempotent if the expected value comes from what the page rendered (hidden field like `seen_completed_at`, or a version), never from a fresh read inside the action. Re-reading lets a late duplicate or stale-page submit see the advanced row and complete the next occurrence too. Seen `app/(app)/maintenance/page.tsx` completeTask.
- Guarded updates (`.eq(col, readValue)` / `.neq('status', x)` + `.select('id')`) stop double submits only when the write changes the guarded value; a no-op step (e.g. `nextDue === due`) or a nullable status column (`neq` drops NULL rows) weakens them. `maintenance_tasks.status` is nullable text (active/paused/completed), `next_due_date` is `date`. Seen `app/(app)/maintenance/page.tsx` completeTask.
- Fix verified (2026-10-08): `complete_maintenance_task` (20261008020000) is INVOKER, CAS on the page's `seen_completed_at` (`is not distinct from`) + due date, all four writes in one txn. Fine to take `p_seen_due` from a fresh read when `last_completed_at` (which every completion changes) comes from the page. Notes go via `mergePrivateFieldsOne` -> history (staff-only RLS) and `calendar_events.internal_notes` (moved by `calendar_events_move_private_fields`).
- maintenance_tasks, calendar_events carry RESTRICTIVE `mgr_assoc_scope` (all commands); `maintenance_task_history` policy requires `can_access_association` of the parent task + `completed_by = auth.uid()`. No extra `managesAssociation` needed for user-session writes there.
- `/accept-invitation` (2026-10-08): page + `acceptInvitation` add a service-client `tokenMatchesAddress` check. That is a host-consistency guard, not a boundary: `accept_invitation` (SECURITY DEFINER, EXECUTE to authenticated) is callable directly via PostgREST from any origin; the real binding is pending + expiry + `lower(inv.email)=auth email` + verified-email trigger. `/invite` already shows company_name to anyone holding the token (unauthenticated), so showing it on the signed-in page leaks nothing new. Tokens are 64-hex, so no rate limit needed for enumeration.
- Tenant-host middleware (3355c8f0, 2026-10-08): robots.txt disallow-all + PLATFORM_ONLY_PATHS 404 + /demo,/legal in MARKETING_PATHS, all inside the resolved-tenant branch before `getUser`. Clean: nothing outside `app/(marketing)` links /demo or /legal (signup links /demo but /signup is already redirected on tenants); the `tenant-workspace-boundary.test.ts` pins it. Early returns there drop any refreshed cookies, same as the existing redirects (acceptable).
- Compensating writes on a lost race (e.g. archive the duplicate after a 0-row CAS link, `app/(app)/inspections/[id]/page.tsx:157`, 2026-10-08) are often left unchecked: require error + `.select('id')` check and say in the message what is left behind. RLS refs: `calendar_event_reminders_staff_scoped` (can_access_association / portfolio when assoc null) matches `calendar_events_staff_all` + `mgr_assoc_scope`; `work_orders_staff_all` lets staff archive, no `archived_at` filter on SELECT; WO insert fires `trg_dispatch_wo_created` webhook, so a duplicate archived later was still announced.

## Next.js pitfalls
- Inline `'use server'` actions capture outer-scope identifiers as encrypted bound args via Flight; a component-scope helper FUNCTION captured this way throws at render ("Functions cannot be passed directly") and breaks the whole page. Helpers used by inline actions must be module-scope. Seen `app/(app)/associations/[id]/committees/page.tsx:54` (2026-10-08). Verify with the SWC transform: scratch script calling `next/dist/build/swc` `transform` with `serverActions:{isReactServerLayer:true,isDevelopment:false,hashSalt:'',useCacheEnabled:false,cacheKinds:[]}` and grep `encryptActionBoundArgs`.
- Editing an already-applied migration does nothing live (`if not exists` guards skip); check Status.md for "Apply after merge" before trusting an edited migration.
