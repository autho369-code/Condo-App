## Helpers / files worth checking
- [Enforced nonce CSP](csp.md) -- blob print docs inherit CSP; prerendered pages lack nonce; matcher-skipped paths get none
- [RLS once-per-query rewrite](rls-hoist.md) -- my_* helpers replace can_* in policy text (2026-10-11); grep/helper-edit drift, portfolio-wide id RPCs
- Tenant headers (`x-tenant-host`, `x-portfolio-id`, ...) are trusted only because `middleware.ts` `INTERNAL_TENANT_HEADERS` strips client copies first; any new internal header must be added there.
- `portfolios` column guards are triggers: `portfolios_guard_platform_columns` (tier, slug, custom_domain...; passes when `auth.uid() is null` or platform admin) and `portfolios_guard_domain_verification` (custom_domain_verified_at; blocks `current_user in ('authenticated','anon')`, so only service role/SQL editor write it). Prefer the `current_user` check for new guards: `auth.uid() is null` also passes anon. New platform-owned columns must join one.
- Auth/Supabase redirect links (reset, invite callback) must stay on `tenantWorkspaceUrl`/`resolvedTenantUrl`; `companyUrl` (verified custom domain) is for plain links only.

- `portfolios` SELECT: staff/company admin only for `current_portfolio_id()` (`portfolios_staff_read`), operators all (`portfolios_platform_read`); owners/board/vendors none. A non-`!inner` `portfolios(company_name)` embed hidden by RLS returns null, not an error. `associations.portfolio_id` is the only FK to portfolios (no ambiguity; precedent `app/(app)/payments/[id]/receipt/page.tsx:24`).
- `me.portfolio` is the caller's profile company, not the record's: operators pass `requireStaff` and see every company, so branding/scoping by `me.portfolio` can mismatch the association (e.g. `lib/rpcs/documents.ts:92`). Prefer the record's own `portfolio_id`.

- Two writers of `portfolios` branding: `app/company-admin/settings/actions.ts` (RPC `update_company_profile`) and `app/(app)/settings/branding/page.tsx` saveBranding; both validate via `lib/company-admin/settings.ts` (`isHexColor`, `normalizeCompanyLogoUrl`, `normalizeWebsiteUrl`, trimmed non-blank name). DB backs it since 20261007050000 (`portfolios_brand_color_hex`, `portfolios_company_name_not_blank`), and `middleware.ts` falls back to #10B981 for non-hex `x-portfolio-color`. Any new raw (non-`setEncodedHeader`) tenant header needs the same allow-list. `support_email` is still free text (used as email replyTo) -- low, pre-existing.
- `.bind(null, id)` args on server actions are NOT encrypted (client can send any); never fall back to them for scoping. `updatePortfolioPolicy` (lib/rpcs/portfolio.ts) fixed 2026-10-07 to ignore it and require `me.portfolio.id`.
- Direct `portfolios` updates hit 0 rows (no error) for callers RLS excludes; check for `.select('id')` + empty-result failure.

- White-label via `me.portfolio` (audit 2026-10-08): emails whose `portfolioId` is the record's company but `fromName`/`replyTo`/`tenantWorkspaceUrl(me.portfolio.slug)` come from the caller's profile company break for operators (requireStaff passes them). Seen `app/api/letters/send/route.ts:77`, `app/(app)/owners/[id]/occupancy-actions.ts:247-275,361-378`. Fix: read the record company's slug/name/support_email. Fixed 2026-10-08 (letters route: other company -> fromName null so queue brands from portfolio_id; occupancy-actions `recipientCompany`).
- `unit_pets`/`owner_vehicles`/`tenants` RLS is portfolio-only (no assoc trigger), and `unit_pets_resident_read` has no portfolio check: `addPet` (`app/(app)/owners/[id]/occupancy-actions.ts:161`) takes unchecked formData `unit_id`/`tenant_id` -> any staff can plant a pet in another company's owner portal. Inserts there must take portfolio_id from the validated owner/association, not `me.portfolio` (operators). Fixed 9bc7a0f5 via `currentHome()` (RLS-read current occupancy + `associations(portfolio_id)` embed; fails closed if hidden). Pattern: a fail-loudly lookup placed AFTER writes (e.g. `recipientCompany` after revoke+insert in `sendTenantPortalInvitation`) leaves partial state; resolve lookups before the first write.
- Form-supplied FK ids are not RLS-checked by the FK. `associations.property_group_id` app writers (associations/new, createBuilding, setPropertyGroupMembers) check the group's portfolio since 2026-10-08, and migration 20261008030000 backs it in the DB (associations + property_groups triggers; `report_data_property_group_directory` join now filters by portfolio). Look for this "app-only FK check" pattern on other cross-table FKs.
- Audit 2026-10-08: all `app/api/**` service-client routes and portal/board/vendor service-client reads were clean (pinned by session ids, tenant, signatures or scoped storage paths).

- AppFolio importers (2026-10-08, branch serene-wozniak): auth + scope clean. `work_orders` private fields (`internal_notes`, `vendor_instructions`) are moved by BEFORE INSERT triggers, so the AFTER `trg_dispatch_wo_created` payload (`to_jsonb(new)`, queued in `webhook_deliveries`, company's own endpoints) never carries them. Read-then-insert dedupe (imported_balances memo, `AppFolio WO #` marker) is not atomic: concurrent runs double-post; `lib/forms/submission.ts` `claimSubmission` needs FormData, so client-called JSON actions need another lock.
- Import lock (`lib/imports/import-lock.ts`, `import_locks` 20261008080000): INVOKER `claim_import_lock` gated by `can_manage_association`, so it is also the association-manage check for importers. Release policy lets any manager delete any lock and `claimed_at` is caller-settable on direct insert: accident guard, not a boundary. `owners` RLS is company-wide (no assoc scope); `owners.notes` -> `owner_private` by trigger. Homeowner import reuses owners by email company-wide: a shared/placeholder email links an owner of another association to this unit (portal exposure); flagged 2026-10-08.
- Homeowner import dues (2026-10-08 diff): new-link path puts unit dues on the first successful new occupancy, but the rerun retry path (`duesRetries`) uses the occupancy matched by the row that carries dues, so a retry can land on a co-owner. No double-scheduling (`state.hasDues` set when queued). `phoneNumberList` handles legacy string entries.
- `units`/`buildings` RLS is association-scoped (`units_staff_all`/`buildings_staff_all` = `can_access_association` via building, + RESTRICTIVE `mgr_assoc_scope`); user-session writes there need no extra `managesAssociation`. AppFolio unit import (`importAppfolioUnits`, 2026-10-08) clean on that basis; client-called actions returning `{errors}` are fine when the client renders them and catches throws.
