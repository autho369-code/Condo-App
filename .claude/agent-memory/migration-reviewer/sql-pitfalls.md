- `auth.uid() is null` = "service role" guards also pass for anon JWTs, SQL editor and pg_cron; OK only while no anon policy/definer RPC writes the table. Trigger-function EXECUTE is revoked automatically by the event trigger in `20261001031000_default_function_privileges.sql`, so no explicit revoke is needed.
- Live ACL of public security-definer functions comes from `20260726050000_security_definer_execution_boundary.sql` (~:534 list): revoke from public/anon/authenticated, grant service_role. `create or replace` keeps ACL/owner/comment, so a replacement needs no grants (but check the COMMENT still matches).
- `add constraint` has no IF NOT EXISTS: flag as low (wrap in `do $$ if not exists (select 1 from pg_constraint where conname=...)`), not blocking. Example: 20261007040000:19.
- Whitespace CHECKs: `btrim(x)` strips only ASCII space, JS `.trim()` strips tabs/newlines/NBSP too, so `btrim(x) <> ''` is weaker than the app check (not stricter). Suggest `x ~ '[^[:space:]]'` as low, never blocking.
- Write non-ASCII characters in SQL as chr(n) (e.g. chr(160) for NBSP): 20261007050000's NBSP became a plain space when applied through the MCP (2026-10-07). Flag literal non-ASCII in constraints/regexes.
- Prod drift (2026-10-07): `portfolios_company_name_not_blank` is `[^[:space:] ]` (plain space) in prod but has a literal NBSP in the repo file 20261007050000:26; the NBSP rule is `portfolios_company_name_visible` (20261007060000, chr(160)). Don't flag the old constraint as a conflict: it is harmless and redundant. Quick non-ASCII scan: `LC_ALL=C grep -nP '[^\x00-\x7F]' <file>`.
- PG regex `[:space:]` is collation-dependent: under libc `C`/`POSIX` it is ASCII-only; glibc UTF-8 locales add U+1680, U+2000-2006, U+2008-200A, U+2028/9, U+205F, U+3000 but NOT U+00A0/U+2007/U+202F. A visible-text CHECK that relies on `[:space:]` for Unicode spaces is locale-sensitive; list them via chr(n) to be explicit (20261007070000:24). Middle dots in SQL comments are harmless non-ASCII.
- JS `\p{Cf}` also covers U+0600-0605, U+061C, U+06DD, U+070F, U+0890-0891, U+08E2, U+FFF9-FFFB and astral Cf (tags U+E0001, U+E0020-E007F, U+1D173-1D17A, ...); DB classes usually omit these. That leaves the DB looser than the app, which is fine for a backstop (low).
- Live-body comparison for definer RPCs: repo history is patched in place by later `pg_get_functiondef` + `replace()` migrations (e.g. void_payable_bill: 20260729020000 -> credit guard 20261001110000 -> full rewrite 20261004161000:313; request_payable_bill_approval text via 20261005094000). Grep the name across ALL later migrations, not just `create or replace`.
- "Visibly blank" checks: use Unicode Default_Ignorable_Code_Point (JS `\p{Default_Ignorable_Code_Point}`, DB class listing its ranges), not just Cf + whitespace: U+FE0F, U+034F, U+E0100, U+3164 (Mn/Lo) slipped past 20261007070000; Codex caught it, fixed in c7df1d6.
- Some live definer bodies use CRLF (advance_delinquency_case, set_delinquency_case_hold): multi-line replace() anchors silently miss; anchor on a single line (inserted LF lines next to CRLF are harmless, idempotency check still matches). delinquency_cases has only `trg_delinquency_cases_scope` (portfolio consistency), no association-scope trigger, so delinquency RPCs need their own `can_view_association_row` (20261007090000; offer RPC done in 20261004130000:220). `sync_owner_delinquency_cases` scoped in 20261007100000 (upsert WHERE + cured UPDATE).
- ON CONFLICT DO UPDATE scope: a WHERE on the SELECT only checks the *new* row; the conflicting existing row is untouched by that filter. Safe when the conflict key pins the scope column (unit_id -> unit's association; delinquency_cases.association_id NOT NULL), else add `do update ... where can_view_association_row(<table>.association_id)` (skips silently). Residual case: unit moved associations -> case retagged (low).
- RLS-helper perf rewrites (20261008050000): PG `inline_function` refuses scalar SQL bodies with sub-SELECTs (hasSubLinks), SECURITY DEFINER or SET, so wrapping helpers in `(select f())` INSIDE the helper blocks inlining. The InitPlan trick only works when `(select ...)` is written in the policy itself. Ask for EXPLAIN (ANALYZE, VERBOSE) as role authenticated before/after.
- Definer -> invoker on RLS helpers: inner helpers' EXECUTE is then checked against the caller at plan init. `is_company_admin()` is revoked from anon (20260728095000:39); ~9 baseline policies with no `TO` role (e.g. automation_flows_staff_all :21559) reach anon.
- SQL->PL/pgSQL helper conversion (20261008050000, `return (select s.x from (<body>) s(x) limit 1)`): checked 2026-10-08, no blockers. Facts: SECURITY DEFINER SQL functions were never inlined, so index/policy inlining is unchanged; no LANGUAGE sql definer helper is STRICT/PARALLEL SAFE/LEAKPROOF/COST or returns composite/record/void (baseline has 0 PARALLEL/LEAKPROOF); none appears in table CHECK, column DEFAULT, generated column or index expression (only policy USING/WITH CHECK); the event trigger in 20261001031000 revokes only `prorettype = trigger`. Watch: a later `create or replace ... language sql` of a helper silently reverts it.
- SETOF uuid helper conversion (20261008060000, `return query <body>`): checked 2026-10-08, no blockers. Definer/SET SRFs are never inlined (inline_set_returning_function refuses them), all 7 bodies return plain uuid columns, no params. `current_board_association_ids_with(text)` would match the catalog filter but was dropped in 20261001052000:80. Catalog-driven selectors (no name list) are low: ask for `proname = any(...)` + count assert.
- Trigger args holding a table name: `regclass::text` is search_path-relative (unqualified when public is on the path); fine with `set search_path pg_catalog, public`, but suggest `%L` of a schema-qualified name / `tg_argv[n]::regclass` (low).
- Checker false alarms (2026-10-09, 20261009040000): `[critical] truncate-table` fires on `revoke ... truncate on <table>` (a privilege, not TRUNCATE); `[high] production-like-seed` fires on an `insert` inside a function body. Confirm by reading the line before reporting.
- Every SECURITY DEFINER function in public lost anon EXECUTE in 20260726050000 (catalog loop), so baseline policies with no TO role that call definer helpers already error for anon; revoking a new helper from anon is not a regression.
- Overloading a function breaks `'public.f'::regproc` ("more than one function named"); 20261005094500:16 uses it for submit_owner_message, harmless on replay (runs before the overload) but later patches must use `'public.f(text,text,uuid)'::regprocedure`. PostgREST named-arg overloads are unambiguous only when neither version has defaults covering the other's arg set.
- INVOKER RPCs cannot call GL helpers (`charge_gl_accounts`, `payment_gl_accounts`, `gl_pick`, `app_gl_map`, `unit_association_id`, `app_period_closed`, `app_ownership_bounds`): EXECUTE is service_role only (20260930020000:229, 20261003200000:79, 20261003210002:29). A rolled-back DO-block compile as postgres does NOT catch it (plpgsql checks EXECUTE at run time); ask for a `set local role authenticated` + jwt-claims run or `has_function_privilege('authenticated', ...)`. Example: 20261009080000:47 (import_opening_credit); fixed in 7a0d262 with a DEFINER wrapper `import_credit_income_account` that re-checks can_manage_finance + can_manage_association (the accepted pattern), re-review clean 2026-10-09.
- Per-call temp tables (`create temp table if not exists ... on commit drop`) in definer RPCs: a bare `delete from _t;` fails under pg_safeupdate for PostgREST callers; TRUNCATE is the fix (20261009090000, reviewed 2026-10-09, clean). TRUNCATE on a session temp table: owner = definer role (postgres), lock is session-local, plans stay valid (same OID); only risk is "used by active queries" if re-entered while a loop over the table is open (callers use `perform`, none do). Checker `[critical] truncate-table` fires on it; by PR rules (precedent 20261009030000:15) Mirsad still runs any file with delete/truncate text in the SQL editor.
- `pg_get_functiondef` + `replace()` patches with an `n <> 1` / `n = 0` raise are not re-runnable (second run finds 0). Suggest `if n = 0 and position(v_new in v_def) > 0 then continue` (low, matches precedent 20260930132000).
- Missed 2026-10-09: 20261009030000 (#264, import_bills) and older csv-import/diagnostic migrations shipped a bare `delete from _t;` in definer RPCs and were passed; Bills upload and Journal entries upload failed in production ("DELETE requires a WHERE clause"). Flag any DELETE with no WHERE in a function body as a blocker.
- RLS hoist (20261011010000/020000, reviewed 2026-10-10): policies no longer contain `can_access_portfolio(x)` etc.; they hold `( SELECT public.f() AS f)` and `x IN ( SELECT public.my_*_ids() ...)` forms. Any later pg_policies regex rewrite must match these forms (and assert a count). `(?<!COALESCE)\(` does not stop re-wrapping: in `COALESCE((x = ...)` the inner `(` is preceded by `COALESCE(`. Equivalence script `scripts/sql/rls-hoist-equivalence.sql` runs as postgres, so it does not test EXECUTE for `authenticated`; ask for `has_function_privilege('authenticated', ...)` on helpers newly called directly by policies. `my_*_association_ids()` scan every association platform-wide (perf grows with tenant count).
